# ☁️ Cloud-Windows — Безкоштовний хмарний робочий стіл Windows

Перетворіть безкоштовну віртуальну машину Windows з GitHub Actions на хмарний робочий стіл, доступний з браузера. Відкрийте вебсторінку — і у вас є ПК з Windows, а коли закінчите — вимкніть його. Цілком безкоштовно.

## ✨ Можливості

- 🖥️ Повноцінний робочий стіл Windows просто у вашому браузері (вебклієнт noVNC)
- 📐 **Автоматична роздільна здатність**: після відкриття сторінки роздільна здатність робочого столу автоматично підлаштовується під розмір вікна браузера — телефони й комп'ютери отримують оптимальне відображення; вона також підлаштовується при зміні розміру вікна
- 🌐 Доступ через Cloudflare Tunnel — без публічного IP, без потреби в NAT traversal
- ⌨️ Вбудований IME Sogou Pinyin, введення китайською працює одразу з коробки (натисніть `Win + Space`, щоб перемикатися між китайською та англійською)
- 🖱️ Підключайтеся з телефона, планшета або комп'ютера
- ⏱️ Кожен запуск триває до ~6 годин, і ви можете скасувати його будь-коли
- 📦 **Версія RustDesk**: є також workflow RustDesk, який автоматично завантажує найновіший інсталятор RustDesk на Робочий стіл

## 🚀 Використання (працює одразу після форку)

### Крок 1: Зробіть форк цього проєкту

Натисніть кнопку **Fork** у верхньому правому куті цієї сторінки, щоб скопіювати проєкт у свій обліковий запис GitHub. Після форку ви опинитеся в репозиторії `your-username/Cloud-Windows`.

> 💡 Навіщо форк? GitHub Actions може працювати лише в репозиторіях під вашим обліковим записом — форк дає вам дозвіл на його запуск.

### Крок 2: Запустіть хмарний робочий стіл

1. Перейдіть на сторінку свого форкнутого репозиторію та натисніть вкладку **Actions** угорі
2. Оберіть workflow ліворуч (оберіть один):
   - **Windows Cloud Desktop**: стандартний хмарний робочий стіл
   - **Windows Cloud Desktop + RustDesk**: стандартна версія плюс автоматичне завантаження найновішого інсталятора RustDesk на Робочий стіл (версія не зашита в код — завжди отримує останній офіційний реліз); коли знадобиться віддалене керування, двічі клікніть, щоб встановити
3. Натисніть кнопку **Run workflow** праворуч — з'явиться діалогове вікно з трьома полями введення:

| Параметр | Опис |
|------|------|
| VNC password | Пароль, який ви вводитимете при підключенні до робочого столу — лише літери й цифри, до 8 символів (напр. `abc12345`). **Запишіть його** |
| Run duration | Скільки хвилин ця хмарна сесія робочого столу залишатиметься активною. За замовчуванням 300 (5 годин), максимум 350 |
| Resolution | Початкова роздільна здатність робочого столу, за замовчуванням 1920x1080; щойно ви відкриєте сторінку в браузері, вона автоматично підлаштується під розмір вікна |

4. Натисніть зелену кнопку **Run workflow** для підтвердження — хмарний робочий стіл почне завантажуватися

### Крок 3: Отримайте URL доступу

1. На сторінці Actions відкрийте запуск, який ви щойно стартували (найверхній — жовта крапка означає, що він працює)
2. Зачекайте приблизно 3–5 хвилин, доки віртуальна машина встановить ПЗ і налаштує тунель
3. Натисніть на крок **启动服务并建立隧道**, розгорніть логи та прокрутіть униз, щоб знайти URL на кшталт цього:

```
https://xxx-xxx-xxx.trycloudflare.com/vnc.html
```

4. Скопіюйте URL і відкрийте його у своєму браузері (вбудований браузер телефона цілком підійде)

### Крок 4: Підключіться до робочого столу

1. На сторінці noVNC, що відкрилася, натисніть **Connect**
2. Введіть пароль VNC, який ви задали на кроці 2
3. Ви всередині — насолоджуйтеся робочим столом Windows 🎉
4. Роздільна здатність робочого столу автоматично підлаштується під вікно браузера приблизно через 10 секунд після відкриття сторінки; зміна розміру вікна запускає автоматичне переналаштування (обирається серед роздільних здатностей, які підтримує ваш GPU)

> ⌨️ Натисніть **Win + Space**, щоб перемкнути метод введення між Sogou Pinyin та англійською клавіатурою.

### Крок 5: Вимкніть, коли закінчите

- Поверніться на сторінку Actions, відкрийте запуск і натисніть **Cancel run** у верхньому правому куті — віртуальна машина буде знищена, а тунель загине
- Він також завершиться автоматично, коли сплине заданий час, тож не хвилюйтеся, що він працюватиме вічно

## ⚠️ Примітки

- **URL змінюється при кожному запуску**: старий URL перестає працювати, щойно попередній запуск завершується, тож завжди використовуйте URL з логів останнього запуску
- **Нічого не зберігається**: коли віртуальну машину знищено, файли, завантаження та стани входу на робочому столі стираються — вчасно переносьте важливі файли
- **Правила пароля**: лише літери й цифри, до 8 символів — довші паролі або з особливими символами можуть не підключитися (з `Authentication failed`)
- **Не натискайте Re-run**: щоб запустити новий робочий стіл, натисніть **Run workflow** — Re-run відтворює старий код
- **Повільне/гальмівне з'єднання**: тунель проходить через Cloudflare; швидкості з материкового Китаю залежать від вашої мережі, але користуватися можна
- **Сторінка не відкривається**: спершу перевірте, чи запуск ще триває (жовта крапка) — якщо його скасовано або завершено, URL мертвий

## ❓ FAQ

| Симптом | Причина / Виправлення |
|------|-----------|
| `loopback connections are not enabled` | Баг старої версії — запустіть новий запуск із найновішим кодом через Run workflow |
| `Server is not configured properly` | Баг старої версії — запустіть новий запуск із найновішим кодом через Run workflow |
| `Authentication failed` | Неправильний пароль VNC або пароль довший за 8 символів / містить особливі символи |
| 502 / 1033 на сторінці | Тунель ще не піднявся або впав — зачекайте кілька хвилин або запустіть знову |
| Роздільна здатність не змінилася автоматично | Зачекайте ~10 секунд; переконайтеся, що розмір вікна браузера справді змінився; деякі нестандартні роздільні здатності не підтримуються GPU, і обирається найближча |

## 🛠️ Хочете налаштувати самостійно?

Файли workflow знаходяться в `.github/workflows/` (`windows-vnc.yml` для стандартної версії, `windows-vnc-rustdesk.yml` для версії RustDesk) — ви можете редагувати їх прямо на сайті GitHub; зміни набудуть чинності після коміту.
